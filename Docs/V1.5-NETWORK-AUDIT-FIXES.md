  than allocating a retained delegate session for each SwiftUI view value.

  error and cancellation. Existing origin, MIME, status and redirect checks remain.
- The visual portfolio launch argument is compiled only in DEBUG; Release starts
  on Home independently of this argument.

  and enabled B023 in the server Ruff configuration.

  share a User-Agent derived from the actual bundle version.
- Added nine XCTest cases and four source-contract regressions; the source checks
  are wired into the existing security-check script.

## Follow-up: capture-shield test gate resolved

Review baseline `1d6e2e9e6aa446d981187c3ea665d9c5dd695b96` is already pushed.
Subsequent diagnosis found the shield test passes alone, but the full-suite failure
occurs with `scene.activationState == .foregroundInactive`, capture inactive and
screen capture false (`shield-full-diagnostic.log`). The existing capture sampler
intentionally treats an inactive scene as unknown and keeps protection in place.
The test incorrectly required the shield to disappear regardless of lifecycle.

Only the test expectation was corrected: active, uncaptured scenes must release
the shield; inactive scenes or captured screens must retain it. Existing pure
state-machine tests exercise both branches, including activation followed by an
explicit inactive capture sample. No production capture logic was changed, no
assertion was replaced with a skip, and no screenshot protection was disabled.

Full-suite rerun: `shield-corrected.xcresult` — 351 tests, 3 existing skips,
0 failures (348 passed). This resolves the test gate noted above, but does not
replace physical-device verification or complete the remaining architectural work.
