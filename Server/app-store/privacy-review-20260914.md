# 隐私资料更正清单（本地候选，尚未发布）

依据 2026-09-14 核对的 App/服务端源码，以及用户提供的 App Store 已发布 12 类型汇总。
本文件不证明 App Store 已保存、不证明官网更新，也不替代正式签名包检查。

## App Store 问卷需要核实的差异

| 项目 | 建议设置 | 实际原因 |
| --- | --- | --- |
| 照片或视频 | App 功能；与用户关联；不追踪 | 管理员鉴权上传，保留发布者记录 |
| 其他用户内容 | App 功能；与用户关联；不追踪 | 合作项目说明与联系人/申请同存 |
| 客户支持 | App 功能；与用户关联；不追踪 | 支持邮件可识别发件人；保留已有披露，不假定匿名 |
| 其他用户联系信息（新增） | App 功能；与用户关联；不追踪 | 联系方式字段允许微信，不只邮箱和电话 |
| 其他数据类型 | 提交前核实是否作为账号认证校验值的补充分类；当前本地声明为关联、App 功能、不追踪 | 这是工程映射，不是 Apple 对本 App 的分类裁定 |

其他已有类别保留原用途；粗略位置保持不与用户关联。不能只按字段数量对齐。
当前本地结构化候选为 `privacy-disclosure.json`，与 `PrivacyInfo.xcprivacy` 一起由
`Scripts/test-privacy-alignment.py` 校验；还核对 App 内/官网政策来源中的联系方式、客服和主动复制说明。
该测试只防止本地材料漂移，不代替实际数据流核验、在线政策与商店页面回读。

App 隐私问卷可以独立于 App 更新修改；但清单文件随安装包提交，改问卷不会替换旧包。
依据：[Apple App privacy details](https://developer.apple.com/app-store/app-privacy-details/)。

## 合作邮件与通知上线前置条件

2026-09-14 主节点只读核对：合作 release fuse 关闭；外部启用、SMTP-ready、收件地址及
加密数据密钥配置均未设置；不存在 phpmailer_init/pre_wp_mail 发信适配，也没有 SMTP 插件。
不能把 `wp_mail()` 函数存在当作可送达。

1. 用户确认发信邮箱，并通过受保护的本机/服务器配置提供 SMTP 授权码（不是登录密码）。
2. 配置经过 TLS 验证的发信通道、站外加密数据密钥和固定合作收件地址；禁止回退明文或默认 sendmail。
3. 在隔离环境验证真实提交、两个任务同事务保存、消息箱/APNs、SMTP 接收和邮箱实收；测试须明确标注。
4. 部署已验证的合作队列定时工作器。已有 push-outbox timer 只证明推送工作器存在，不证明合作 sweep 在运行。
5. 完成 schema/删号并发、主备角色及回滚验收后，才发布包含已审核启用开关的新服务端版本。
   当前候选仍保留 release fuse=false，原发布器的强制关闭门禁没有放宽。
6. 再回读线上 capability 与隐私政策，并决定是否替换当前已提交的审核包。

新代码把管理员通知与邮件作为独立任务，管理员通知先入队；对每个管理员用固定幂等键
保存云消息，然后复用 APNs 队列。重复执行不重复建消息，个别失败不撤销其他人的已存消息。
仅提醒有新邀约，不把联系人、预算或项目正文放入推送；详情仍需当前合作管理权限。
真实邮件实收、推送横幅和生产启用均尚未完成。
