# 合作邀约加密存储接入

候选 `v1.4.0-build2-preflight10`，2026-09-06，插件 **1.5.13.4**。
只更新独立开发分支；没有生产部署、真实邮件、用户操作或 TestFlight 上传。

## 实际接入

- 加密组件纳入 vendor 发布单元并由主类加载。真实提交事务只写入认证加密的 `private_payload`，不再写联系人、联系方式或项目详情明文列；幂等指纹改为带独立密钥的 HMAC。
- 管理员列表、状态更新与邮件队列从同一密文读取。损坏、错用户或错请求密文失败关闭，不返回虚假的空白资料，也不向邮件服务发送空白邀约。
- Schema 2 不自动迁移或删除旧明文字段；检测到旧字段便拒绝启用，需要另行审核迁移。删号清理不要求能解密数据或密钥仍然可用。
- 加密密钥必须为独立 32 字节原始随机文件，使用规范绝对路径，位于 WordPress Webroot 外且无组/其他用户权限；拒绝链接、非普通文件、越界和错误长度，校验打开前后 inode。没有生成生产密钥，也不复用 Apple 密钥。
- 发布探针扩展为七个模块及一个入口，继续逐文件哈希校验、隔离执行并验证生产熔断保持关闭。

## 验证

- 独立 Linux PHP 8.3：539 项密文、篡改、字段、文件密钥及幂等指纹断言通过。
- 实际 dormant trait 的 schema 元数据/故障测试：444 项通过。相较旧 schema 的 486 项，减少来自移除七个明文字段后按每列展开的断言；既有错误注入类别没有删除。
- 真实隔离 WordPress 7.1 / MySQL 8.0.46：168 项通过。包括真实提交 SQL 不含合成联系人标记、数据库行不含明文、重复提交/冲突、管理员列表/状态更新、完整邮件正文、邮件队列拒绝后重试/接受后不重复执行、密文损坏及缺钥删号。损坏内容不会到达邮件传输层，并使用不含个人信息的独立错误码，避免误报为邮箱故障。邮件通过 `pre_wp_mail` 合成接收/拒绝，未调用真实传输；不能当成送达证明。
- PHP 插件、推送所有权和 worker 既有回归通过。源码门禁通过，Ruff、供应链锁定策略通过；最终错误码及哈希更新后复验受影响的 PHP/发行契约。macOS 缺少 PHP、Composer 和 Linux flock 的部分没有冒充本地执行；PHP 另在上述 Linux 隔离夹具执行。
- 实际执行发布脚本中的 PHP evaluator：八段源码正确加载并保持硬关闭；改动一个字节或截断输入分别返回哈希/分帧错误，不能输出成功哨兵。这不是生产部署或服务器回滚演练。
- 所有真实数据库测试使用随机独立空库并在 finally 精确移除，未读取生产 WordPress 配置或真实用户。
