# 合作存储真实 WordPress 升级回归

版本记录：`v1.4.0-build2-preflight3`，2026-09-06。本增量只增加显式集成测试和验证说明；App、插件运行源码、签名构建和生产功能开关均未改变。

## 目的与实际范围

此前的 486 项元数据故障断言与 28 项 MySQL 断言没有执行真实 WordPress `dbDelta`，不能替代 WordPress 升级运行时。新测试补上此缺口，而不是把原测试重新命名为端到端通过。

- 对照服务器只读版本结果，使用 WordPress 7.1、PHP 8.3.6、MySQL 8.0.46。
- 使用 `wp core download --version=7.1 --locale=en_US --skip-content` 下载独立核心，再用 `wp core verify-checksums` 校验；未复制生产配置、插件、媒体或用户数据。
- 测试目录为新建的 `/tmp/yishu-wordpress-schema.TvUcLB`，root 所有、`0700`。官方下载文件初始为组可写，隔离入口按预期拒绝；仅在测试目录将核心文件规范为 `0644`、子目录 `0755` 后继续。没有更改生产目录权限。
- 通过 `systemd-run` 使用 `PrivateNetwork=yes`、`NoNewPrivileges=yes`、`ProtectSystem=strict`、`ProtectHome=yes`；唯一可写目录为上述临时目录，`/var/www`、`/var/lib/mysql`、`/etc/shuzijun` 不可访问。测试只经已有本地 Unix socket 连接 MySQL，自行创建不可指定的随机空库，结束时精确删除它。
- 启动独立 WordPress 核心与真正的 `wpdb`，在新库内安装合成测试站点；内存随机产生测试口令及盐，不写入配置或输出。核心邮件调用被短路，HTTP 请求被拒绝，网络命名空间也与宿主隔离。没有邮件或 APNs 发送。
- 只将既有 dormant trait 加载到独立 Harness 类，不加载生产 API 入口、生产 WordPress 或绕过生产功能熔断。

## 结果

最新完整运行 **36 项断言通过**：

- 真正 `dbDelta` 首次创建三张表，完整结构验证后才记录 schema 就绪；重复升级不发出 DDL。
- 真实字段长度、缺失字段、缺失索引可以完成兼容修复；每次修复后重新验证实际结构。
- 对真实升级 SQL 注入合成语法错误时，不能把 `dbDelta` 的“尝试变更”返回值当作成功，不能写入 ready 版本；解除故障后重试恢复。
- MyISAM 引擎与不完整唯一索引无法被 `dbDelta` 自动“认可”；拒绝就绪，只有显式修复测试结构并复核后才恢复。
- 测试始终连接同一个新建测试库，没有加载生产 API 类或调度合作 worker。

额外验证：在宿主网络命名空间直接调用时，于连接/创建数据库前拒绝执行；全部测试结束后，`information_schema` 中匹配严格随机测试库前缀的数据库数为 **0**。仅合成测试数据库被删除，不存在生产数据恢复问题。

隔离源码工作树的 `Scripts/security-check.sh`、供应链契约及发布清单契约通过。本机没有 PHP/Composer，未将对应本地跳过项宣称通过；本次 PHP 集成验证来自上述真实隔离运行。
