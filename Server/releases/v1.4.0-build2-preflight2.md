# 云端原生 Python 工具链修正

版本记录：`v1.4.0-build2-preflight2`，2026-09-06。仅修改 CI 质量工具链及其验收契约，不改变 App 版本、界面、生产 Python 运行环境或服务端发布状态。

## 原因与修正

- 账户的免费 Actions 分钟数已用完，原来的超额预算为零。按用户明确授权，将现有 Actions 月预算设置为 USD 10，保留达到上限停止使用和 75% / 90% / 100% 邮件提醒，其他产品预算不变。
- 账户恢复运行后，[iOS Quality Gate 34009001169](https://github.com/Saruika/shuzi/actions/runs/34009001169) 实际完成启动、签出，但 Python 安装报错：锁定的 3.12.14 没有适用于当前 macOS ARM64 的安装包。后续测试当时尚未执行，不能归为 iOS 测试失败或通过。
- 改为精确锁定 Python 3.13.15，并显式选择 `architecture: arm64`，保持 `check-latest: false`。官方 [Python 发布页](https://www.python.org/downloads/release/python-31315/) 和 [GitHub 安装包清单](https://github.com/actions/python-versions/blob/96cf261124d1e3fbc49339879ac37f935c25653f/versions-manifest.json) 均已核验；对应原生安装包为 `python-3.13.15-darwin-arm64.tar.gz`，发行标记 `3.13.15-31064747964`。
- 依据新的解释器重新生成带哈希的 CI 依赖锁。37 个包仍精确锁定；唯一移除的依赖为在此解释器版本不再需要的 `typing-extensions`，没有顺带升级剩余依赖。生产 entitlement verifier 的输入和依赖锁未改变。
- 已核对当前 GitHub [运行器镜像说明](https://github.com/actions/runner-images/blob/macos-26-arm64/20260831.0337/images/macos/macos-26-arm64-Readme.md)：镜像 `20260831.0337.3`，默认 Xcode 26.6 / 17F113，与既有策略一致。保留每次运行的真实镜像、工具版本和二进制摘要记录，不改用浮动 Python 或 x64 兼容层。
- 不删减 SAST、SCA、SBOM、iPhone/iPad 或 Release 编译检查；不改历史版本记录。新增契约检查要求 Python 安装步骤选择原生 ARM64 且不自动追逐新版本。

## 验证边界

- 本机隔离环境已安装 Python 3.13.15 / arm64，使用 `pip --require-hashes` 安装全部质量依赖，`pip check`、依赖策略及修改文件 Ruff 检查通过。
- 新解释器下的供应链与服务端发布契约通过；隔离 Git 候选树的 `Scripts/security-check.sh` 通过。本机缺少 PHP/Composer，未将本地跳过项目宣称通过；这些项目仍由云端执行，上一版真实 PHP/MySQL 结果保留在独立记录。
- Ruff 全树通过；Bandit 中/高风险门槛通过，保留既有 7 项低级别发现及 1 项精确文件权限例外，没有全局关闭规则。CI 质量依赖 37 项和生产 Python 依赖 33 项本次查询未发现已知漏洞，逐项覆盖验证通过；生成 68 个组件的 SBOM。
- 完整云端 iOS 矩阵结果仍须实测；上述本机检查不能替代云端通过。
- 同步锁回归已在 GitHub 成功运行；该结论不代表全部 App 功能验收完成。
- 本版本没有上传 TestFlight、提交 App Store、开启合作自动邮件或修改生产服务。
