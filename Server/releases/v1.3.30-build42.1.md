# Hi，梳子 1.3.30 / Build 42.1 签名同步恢复候选

本记录固定上海 authority `101.43.79.80` 到新加坡 standby
`129.226.202.207` 的签名同步 v4 候选。上海继续是唯一主写节点和 CDN
主源；本发布不修改 DNS、CDN 源站顺序、帐号 API 路由或故障转移状态。

## 根因与基线

自动同步停止不是服务器崩溃。旧 root cron 在收敛单写节点时被有意
移除，新 timer 为等待完整安全审计而保持 disabled/inactive，因此没有
任务会自动发起。已接受基线为 generation 6：

- 上海 `highest-issued-generation=6`，新加坡 `highest-accepted-generation=6`；
- 两边媒体均为 943 个文件、209,133,527 bytes；
- 数据库、App Content、公网首页关键标记一致；
- Nginx、PHP-FPM、MySQL 和 Redis 正常，故障转移继续禁用。

上海到新加坡的旧链路实测有约 31.5% TCP 重传，所以完整媒体同步保留
8 小时有限 deadline。v4 仍传输完整签名快照；增量/去重不在本恢复范围内。

## v4 事务边界

- 上海在最后的数据库和媒体激活窗口前完成 staging 与全部预检；
  新加坡在 Web 根目录外构造 uploads release，用同文件系统原子交换。
- 两节点的站点变更共用 root-only
  `/var/lib/shuzijun-sync/site-operation.lock`，并与每日快照锁互斥。
- 独立 FPM guard 覆盖 TERM、KILL、SIGSTOP、RuntimeMax、重启与 delayed stop；
  无 durable commit 时必须持久隔离 FPM。
- `release_id` 与每次启动的 `activation_nonce` 分离。已持久化的 commit
  永不回滚；I/O、超时或损坏状态不得被当作“不存在”。
- SSH 仅允许密码锁定的 `shuzijun-sync-transport`，固定主机公钥、
  forced-command gate 和 `--attest` / `--protocol` / `--ingest` 三个精确 sudo 命令。
- 数据库原始流上限 4 GiB，gzip 上限 8 GiB；路径、文件数、单文件、
  总大小、临时空间和输入时间都有硬上限。
- 仅允许通过 `systemctl start shuzijun-sync.service` 运行同步，不允许直接
  调用 sender 绕过 Nginx preflight。

## 部署门禁

`deploy-shuzijun-sync-release` 是唯一发布入口。它从固定的 root-only
`/run/shuzijun-sync-release/{backup,primary}` 读取精确 allowlist，在任何
现场备份或变更前复核候选 SHA-256、节点角色、服务状态和 generation 6
前置条件。`--dry-run` 零写入；`--apply` 建立 root-only 完整回滚包。

生产顺序固定为：

1. 新加坡 `backup standby --dry-run`，然后原参数 `--apply`。
2. 从该已提交事务中取得原字节 `standby-first.receipt`，以 root:root
   0600 安装到上海 primary stage。
3. 上海 `primary authority --dry-run`，然后原参数 `--apply`。
4. 两节点重新校验已安装字节、角色、服务、后台进程、站点语义、
   DNS/CDN 路由和回滚包终态。
5. 运行一次前台 generation 7。只有 issued、accepted、active-release、sender
   completion 和 receiver commit 都精确为 7，且 guard/FPM/站点健康通过后，
   才允许启用 persistent timer。

任何一项未通过都必须保持 timer disabled/inactive。已消耗的 generation
不得减小、删除或重用；故障转移必须继续 disabled/inactive。

## 审计、系统更新与告警

冻结候选已通过 macOS、Linux root 和真实 systemd 255 fixture，包含
TERM/KILL/SIGSTOP、延迟 stop、RuntimeMax、start-limit、guard 缺失/损坏、
durable commit、hardlink/FIFO/gzip 和事务回滚窗口。测试后无残留 unit、进程或
runtime 目录，独立审计无 P0/P1/P2 问题。

上海已安装 10 项 Ubuntu 安全更新，新加坡当时无待更新；两边待安全更新
计数均为 0，不需要重启。腾讯云已创建并回读三项已启用的 Lighthouse、
CDN 和 TLS 证书策略，共用短信+邮件通知模板。这些不等于内部
Nginx/PHP/MySQL/同步语义告警；本版未在无单独计费确认时开通 Prometheus。
