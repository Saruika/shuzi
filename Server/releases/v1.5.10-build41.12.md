# App Content API 1.5.10 / Build 41.12 健康监控安装器发布记录

该记录随 Git 标签 `v1.3.29-build41.12` 保存。Build 41.11 已发布 GitHub，
但备用节点执行到 `PREPARED` 后，停止 timer 使 inactive health service 失去
active unit 引用并被 systemd 回收；随后 `reset-failed` 对未加载 unit 返回
非零。事务尚未备份或替换 runtime，按 fail-closed 停止 health timer。现场已
确认旧 script/service/timer 哈希未变，恢复旧 timer 后显式运行一次旧 health
service，重新建立五分钟排程，并在 root-only 事务目录写入耐久
`RECOVERED` 标记。Nginx、PHP-FPM、MySQL 全程 active。

Build 41.12 新增固定 health service 的隔离归一化 helper。它尝试
`reset-failed`，但不依赖本地化错误文本或命令返回值；随后通过两次独立采样
严格证明 unit 已从磁盘加载、状态为 `inactive/dead` 且 Job 为空。只有该终态
连续成立才允许备份、替换或回滚恢复；failed、active、not-found、masked、
残留 Job、属性读取失败或两次采样漂移都会 fail-closed。主事务与 rollback 的
首次隔离共用此 helper，active timer 固定后的显式运行路径保持原有严格门禁。

## 生产启动门禁

不得直接执行仓库副本。先把标签中的安装器原子安装到
`/run/deploy-shuzijun-health-build41.12`，设为 `root:root 0700`、regular、
non-link、nlink=1；三个 runtime 候选分别放入仅含这三项的
`/run/shuzijun-health-build41.12-backup` 和
`/run/shuzijun-health-build41.12-primary`。备用节点必须先成功。

```bash
sudo /usr/bin/env -i PATH=/usr/sbin:/usr/bin:/sbin:/bin LC_ALL=C LANG=C /bin/bash --noprofile --norc -c '
set -Eeuo pipefail
DEPLOYER=/run/deploy-shuzijun-health-build41.12
DEPLOYER_SHA256=4693d935bd56a809677a2283bae347bdf7d7ceaeaba3f03bfeac44615e542c5d
[[ ! -L "$DEPLOYER" && -f "$DEPLOYER" ]]
[[ "$(/usr/bin/realpath -e -- "$DEPLOYER")" == "$DEPLOYER" ]]
[[ "$(/usr/bin/stat -c "%F:%u:%g:%a:%h" -- "$DEPLOYER")" == "regular file:0:0:700:1" ]]
[[ "$(/usr/bin/sha256sum -- "$DEPLOYER")" == "$DEPLOYER_SHA256  $DEPLOYER" ]]
exec /bin/bash --noprofile --norc "$DEPLOYER" backup standby
'
```

备用节点完整验收通过后，主节点仅将最后一行替换为：

```bash
exec /bin/bash --noprofile --norc "$DEPLOYER" primary authority
```

## 验收与操作边界

- standby 必须为 schema 2、`role_verified=true`、`critical_reasons=[]`，且只包含
  `standby_failover_state_unhealthy_or_stale`、`standby_failover_timer_disabled`、
  `standby_sync_generation_missing_or_invalid`、`sync_log_generation_missing_or_invalid`。
- authority 必须只包含 `authority_sync_generation_missing_or_invalid`、
  `sync_log_generation_missing_or_invalid`、`sync_timer_missing_or_disabled`。
- 两节点 runtime 与 loaded typed Exec 哈希一致，核心服务 active，固定路由
  全部 `ok=true`，health service 必须以 degraded/exit 2 被 systemd 记为 success。

该事务不运行同步或故障切换，不修改 DNS、CDN、Nginx、PHP-FPM、MySQL、
WordPress 内容或媒体。有效 `DONE` 是提交点；事务前门禁或隔离失败必须
fail-closed，不得误报成功。
