# App Content API 1.5.10 / Build 41.10 健康监控安装器发布记录

该记录随 Git 标签 `v1.3.29-build41.10` 保存。Build 41.9 已通过空锁文件
校验，但备用节点的旧 oneshot 当时是 `failed`；`systemctl stop` 不会自动
清除该状态，因此事务在 `PREPARED` 后、备份和 runtime 替换前拒绝。当场
复验确认旧 script/service/timer 哈希未变，然后仅执行 `reset-failed`、
恢复旧 timer `enabled+active`，并在该 root-only 事务目录写入耐久
`RECOVERED` 标记。Nginx、PHP-FPM 和 MySQL 全程 active。

Build 41.10 在主事务和回滚隔离段均增加显式 `reset-failed`，严格要求
service 归一到 `inactive/dead` 后才允许备份、替换或恢复 timer。合同测试
会模拟“stop 后仍 failed”，缺少 reset 时必然失败。
它还删除 timer 刚 start 后的过早 next-elapse 整数断言；systemd 在立即触发
期间可返回无穷大。现在先等待 oneshot 和调度稳定，再使用两次有界
D-Bus 微秒采样验收，并用动态立即触发回归覆盖。

## 生产启动门禁

不得直接执行仓库副本。先把标签中的安装器原子安装到
`/run/deploy-shuzijun-health-build41.10`，设为 `root:root 0700`、regular、
non-link、nlink=1；三个 runtime 候选分别放入仅含这三项的
`/run/shuzijun-health-build41.10-backup` 和
`/run/shuzijun-health-build41.10-primary`。备用节点必须先成功。

```bash
sudo /usr/bin/env -i PATH=/usr/sbin:/usr/bin:/sbin:/bin LC_ALL=C LANG=C /bin/bash --noprofile --norc -c '
set -Eeuo pipefail
DEPLOYER=/run/deploy-shuzijun-health-build41.10
DEPLOYER_SHA256=4f36f9ee749af33d1b155d4a8e8d32ee31240b7a7688721a028af2738c7f7ffc
[[ ! -L "$DEPLOYER" && -f "$DEPLOYER" ]]
[[ "$(/usr/bin/realpath -e -- "$DEPLOYER")" == "$DEPLOYER" ]]
[[ "$(/usr/bin/stat -c "%F:%u:%g:%a:%h" -- "$DEPLOYER")" == "regular file:0:0:700:1" ]]
[[ "$(/usr/bin/sha256sum -- "$DEPLOYER")" == "$DEPLOYER_SHA256  $DEPLOYER" ]]
exec /bin/bash --noprofile --norc "$DEPLOYER" backup standby
'
```

备用节点完整验收通过后，主节点仅将最后一行替换为：

```bash
exec /bin/bash --noprofile --norc "$DEPLOYER" primary authority
```

## 验收与操作边界

- standby 必须为 schema 2、`role_verified=true`、`critical_reasons=[]`，且只包含
  `standby_failover_state_unhealthy_or_stale`、`standby_failover_timer_disabled`、
  `standby_sync_generation_missing_or_invalid`、`sync_log_generation_missing_or_invalid`。
- authority 必须只包含 `authority_sync_generation_missing_or_invalid`、
  `sync_log_generation_missing_or_invalid`、`sync_timer_missing_or_disabled`。
- 两节点 runtime 与 loaded typed Exec 哈希一致，核心服务 active，固定路由
  全部 `ok=true`，health service 必须以 degraded/exit 2 被 systemd 记为 success。

该事务不运行同步或故障切换，不修改 DNS、CDN、Nginx、PHP-FPM、
MySQL、WordPress 内容或媒体。有效 `DONE` 是提交点；事务前门禁或
隔离失败必须 fail-closed，不得误报成功。
