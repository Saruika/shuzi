# Hi，梳子 1.3.30 / Build 42.3 旧单元启动合同修复

Build 42.3 取代 Build 42.2 作为生产候选。新加坡的 42.2 预检在任何
生产变更前再次失败关闭：发布器要求旧健康 service 直接执行
`/usr/local/sbin/shuzijun-internal-health`，但已固定 SHA-256 的旧 service
一直使用：

```text
ExecStart=/usr/bin/python3 -I /usr/local/sbin/shuzijun-internal-health
SuccessExitStatus=2
```

现场 D-Bus `ExecStartEx` 回读与上述文件精确一致。本版将旧单元预期修正为
固定 `/usr/bin/python3 -I` 命令及参数，并在合同中同时断言仓库 service
的 `ExecStart` 和 `SuccessExitStatus`，防止文件哈希与运行时属性再次自相矛盾。

42.2 尝试后已证明：健康监控脚本、service、timer、status、私有日志、
root crontab 与快照 cron 均未改变，timer 仍 enabled/active，快照锁空闲，
未生成 Build 42.2 事务备份。

```text
HEALTH_DEPLOYER=1f78eceb497e11c61cb3ae156718b96241d1d9fbed07327cb0f0508299145284
HEALTH_DEPLOYER_TEST=fdd0b6e66179185607e72a1dc24c75b5d2616f3fecf1b8c4c7ef37df2a3fd329

```

固定路径与 stage 现为 `build42.3`。必须重新通过健康发布合同、全量
`Scripts/security-check.sh`、`git diff --check` 与生产现场预检后，才能按
新加坡、上海顺序部署。签名同步核心字节不变；本修复不修改
DNS、CDN 主源、故障转移或 generation 计数。
