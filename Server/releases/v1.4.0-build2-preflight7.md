# 首次通知授权与完整 UI 套件的模拟器隔离

版本记录：`v1.4.0-build2-preflight7`，2026-09-06。未上传 TestFlight、未部署生产、未提交 App Store 审核。仅调整 CI 测试设备生命周期，不修改 App 页面、通知授权产品行为或测试断言。

## 已证实的原因

云端 run `34009741458` 的原始诊断 ZIP 已完整下载，SHA-256 校验为 `792a594c0f6f13200f6a8a968b3a193e3d25c1d45d1a3b54ba6b28e9b45c965a`，与 GitHub 发布值一致。两项关于页横屏失败的截图均显示未处理的系统通知授权弹窗，底层首页导航因此不可点击。

原 CI 在一个新模拟器验证首次通知授权并删除它，随后却回到尚未授权的模板模拟器跑完整套件。单元测试启动 App 宿主时可以触发系统授权弹窗；后续 UI 测试的跳过启动授权参数并不能消除先前已经打开的系统弹窗。

已在本机全新 iPhone 17 Pro Max / iOS 26.5 重现同样顺序：188 项单元测试通过，关于页四项配置中两项因同一“主导航不可点击”断言失败；本地失败截图同样出现系统通知授权弹窗。因此此前云端 26.2 / 本机 26.5 的差异不是已证实根因，真正可复现的条件是首次授权状态与测试执行顺序。

## 修正边界

- 模板只提供硬件类型和运行时，不在模板上运行测试或清除其数据。
- 首次授权测试与完整套件顺序运行在同一台新建模拟器上，先实际完成系统授权，再执行单元及 UI 测试。
- 完整套件不加 only-testing、不减少功能覆盖，只避免重复执行已经单独验证的首次授权测试；共用构建输出、保留独立结果包和代码覆盖率。
- 成功、首次授权测试失败、完整套件失败均在退出时清理唯一自建的模拟器；不清理模板或其他设备。
- 保留旧的三参数“只测首次授权”调用方式；完整调用增加独立结果路径。
