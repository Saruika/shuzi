# 首页触摸立即使旧轮播计时失效

候选 `v1.4.0-build2-preflight11`，2026-09-06。未改图片、布局、动画样式、播放器或权限。

## 状态层复现与修正

旧实现由 `HomeHeroPlaybackState.isTouching` 保存触摸状态，但只在 SwiftUI `.onChange` 回调中增加计时 generation。若界面尚未处理变化，按下/松开回到原值时，状态对象中旧计时的 generation 仍相同。它不能在触摸回调当下保证旧自动翻页任务失效。

从修正前真实 HomeView 源码提取状态类，保留 Observation 宏，使用 Swift 执行同一轮调用中的按下/松开，断言失败（退出 1）：`a complete touch before the next SwiftUI update leaves the old timer generation valid`。修正后相同状态探针通过（退出 0）。探针只为未使用的 UIImage 类型提供空替身，不加载照片、SwiftUI 页面或 iOS 模拟器；这是状态层证据，不是实际手势/页面已全面修复的证明。

将 generation 更新移到 `isTouching.didSet`，在真正的状态边缘立即递增；移除异步依赖的 `.onChange`。按下即失效，松开开启新的完整等待周期；重复按下/松开通知不重置周期。新增 XCTest `testHomeContactInvalidatesAutoAdvanceBeforeAnotherViewUpdate` 覆盖这些边界。

## 验收边界

- 状态探针：修正前失败、修正后通过。
- `Scripts/security-check.sh` 源码门禁通过；不具备本机运行条件的 PHP/Composer/Linux flock 不计作本轮本地执行。
- 新增的 iOS XCTest 及原有手动翻页、长按暂停等 UI 回归待运行，不把 macOS 状态探针当作 iOS 全套验收。
- 云端 #132 固定在 `c89692e`，本地 iPad 正在运行的 App 也仍是旧源码；保留完整结果，不中断、不混用新旧构建结果。待这轮结束后再串行验证修正，避免并发模拟器干扰。
- 此前 iPhone 全套 7 次间歇失败仍未全部关闭。本修正处理独立状态竞争，不能据此把所有失败标记为已解决。
- 未上传 TestFlight、过期构建、部署服务器或提交 App Store。
