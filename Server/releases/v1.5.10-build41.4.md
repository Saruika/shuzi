## 修复内容

Standby 首次种子会正确安装 1.5.8 live manifest，但旧普通发布器
只备份和替换 PHP、Composer 两个文件与 `vendor/`。因此升级到 1.5.10
后会留下“1.5.10 payload 加 1.5.8 live manifest”的错误发布证明。

新发布器仅接受审核记录中的 1.5.8/1.5.10 manifest，并在改动前使用
live manifest 严格校验全部当前 payload。唯一无 manifest 例外是 authority
节点精确的 1.5.7 PHP 加 1.5.8 支持文件的一次性 bootstrap 过渡态；
standby 或任何其他缺失状态都失败关闭。

Apply 在 Web root 外备份原 manifest 的字节与存在/缺失状态，并用
独立 `backup-integrity.sha256` 封装备份。新 payload 安装完成后，bundle
manifest 在同一文件系统中先同步、再原子换入，且自身 SHA-256
必须等于 Git/CI 的独立信任值。失败回滚会先恢复 payload，再恢复原
manifest 的精确字节或精确 absent 状态；任何恢复或验收不完整都保持
PHP-FPM 持久隔离。
