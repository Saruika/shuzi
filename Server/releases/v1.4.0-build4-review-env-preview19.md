## 根因与范围

- 最新候选 a6d9a0d 的完整云端 [#133](https://github.com/Saruika/shuzi/actions/runs/34065208117)
  于 06:52 终态失败。Python/PHP 安装、运行器来源采集和 hash-locked 工具安装成功；
  `ci-supply-chain.py validate` 成功，随后契约的 `test_release_record` 失败。
- preview15 / preview18 更新了工作流摘要与分析覆盖，但契约仍把当前工作流与
  Build 2 preflight13 的不可变旧指纹比较。当前工作流指纹为下方 WORKFLOW_SHA256；
  旧记录为 46f348da9b4a75db7bda4bd41d3b4df92471b467caa38ad44638af89bd4ec571。
  在本地单独调用旧 `test_release_record`，已复现同一断言失败。
- 保留历史发布记录不变；当前契约显式引用本记录，继续精确比较文件 SHA-256。
  增加摘要脚本和发行包检查脚本的材料指纹，不移除任何原有检查。
- 指纹检查现在报告具体材料名称；缺失、错误、重复、互相冲突、正文内嵌和尾随内容
  均必须拒绝。不会通过跳过检查或接受任意指纹使云端变绿。
- 本机旧 Python 3.12 质量环境不满足运行器契约的 3.13.15；该失败与工作流指纹
  是两个独立事实。完整本地契约必须使用实际 Python 3.13.15，不伪造版本或跳过来源检查。
- 在复跑云端前执行同一 Bandit 范围，发现审核实例部署工具的 CLI 配置目录使用共享临时目录。
  改为每次调用单独生成的 owner-only 临时配置目录，命令成功、失败及超时均清理；
  不修改调用者环境、不使用共享配置或继承真实用户配置、不增加 nosec 忽略项。
  只修改候选工具，未重跑实例部署或触碰现有审核/生产数据。
