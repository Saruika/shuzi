# 1.4.0 (4) 候选：全屏背景与原生沉浸栏位

日期：2026-09-06（UTC+8）。本记录是客户端候选，不代表已经上传 TestFlight。

## 修复范围

- 保留 1.3 的大图、左下文案、白色作品按钮和轮播指示器，不重新设计画廊。
- 统一主题背景延伸到状态栏及底部安全区；移除强制不透明导航栏与旧版 UIKit TabBar 外观覆盖。
- 使用 SwiftUI 原生自动栏背景：iOS 17–18 Material，iOS 26 原生玻璃；push 页面沿用统一导航容器。
- 首页照片单独覆盖全窗口，天气、文案与按钮根据真实安全边距定位。横屏前景保持原比例完整构图。
- 修复旧嵌套分页 TabView 约 10.67pt 的垂直偏移：改用 iOS 17 原生 ScrollView 分页，沿用原来的预加载和触摸暂停状态。
- 补齐非第 1 张启动及窗口旋转后的显式页码定位，防止页码与实际可见照片分离。
- 关闭仅首页横向照片容器的 iOS 26 垂直滚动边缘遮罩；普通页面仍保留原生滚动磨砂。
- 局部文字渐变对齐实际文案区域，保留原先最大 0.48 透明黑色强度，避免移除系统遮罩后标题对比度不足。
- 不修改播放器、账号审批、管理员权限、照片内容或磁盘缓存策略；不部署服务器、不发送通知、不执行旧包过期。

全局代码、Tab/push 示例和 API 边界见 [实现说明](../../DESIGN_IMMERSIVE_CHROME.md)。

## 诊断过程中发现的问题

- 恢复版 Build 3 的完整 iPhone 回归最终退出 65：208 单元通过；UI 执行 106 次，94 通过、10 跳过、2 对比度失败，并非完整通过。该历史结果保留在 `/tmp/yishu-build3-full-phone.xcresult`。
- 初版全屏修复的几次几何与像素专项失败，分别定位到嵌套分页容器偏移、iOS 26 底部遮罩、标题对比度；修复后重新运行，不删除或忽略原有辅助功能断言。
- iPad 首次专项发现非首张启动时 ScrollView 没有实际滚到所选页，已加入原生 ScrollViewReader 初始/窗口变动定位，以及非首张启动回归；最终结果以上方设备记录为准。
- 隐私政策底部单点及横向窄条取色读到了滚动正文的字形，截图确认并非背景色带。验收改为检查左右正文留白内的顶部、底部背景像素，保留 RGB 误差上限 18；实色黑带仍会失败。
- 新增首页像素验收使用合成色彩图，隐私页诊断截图没有作品照片；不新增 App 照片磁盘缓存。

## 发布与平台边界

- 客户端构建号更新为 `1.4.0 (4)`；TestFlight 当前可下载版本仍为 `1.4.0 (3)`。
- 机器只安装 iOS 26.5 模拟器运行时；最低部署目标继续为 iOS 17，新增 API 按版本保护。iOS 17/18 运行时和真机尚未完成验收。
- iOS 17 不存在 iOS 26 的原生 TabBar 滚动最小化接口，采用用户允许的自动磨砂，不用私有接口模拟自动隐藏。
- 既有截图保护兼容层仍不是 Apple 文档保证的通用截图 API，本次只调整其宿主画布边界，不改变该风险边界。
- 真实管理员生产端到端链路、正式上架资料和完整云端矩阵仍需后续独立验收，不计为本轮 UI 修复已完成项。
