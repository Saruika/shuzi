# Hi，梳子 1.3.30 / Build 42.10 签名同步 v4 健康收据兼容修复

该记录随 Git 标签 `v1.3.30-build42.10` 保存。本版修复备节点健康
监控仍读取旧版单字段提交标记的兼容缺口：签名同步 v4 已将权威
提交收据升级为“代数、发布标识、随机标识”三字段，老健康运行时会将
真实成功的同步误报为提交代数缺失或无效。

- 健康运行时只从 root 专用目录读取
  `fpm-activation-guard-v4.committed`，继续执行无符号链接打开、所有权、
  权限、单硬链、同文件系统与稳定快照校验。
- 收据必须精确符合
  `<positive-generation> <64-lowercase-hex> <64-lowercase-hex>\n`；向状态
  JSON 只输出已验证的整数代数，不暴露发布标识或随机标识。
- 健康监控只对提交收据执行信任与字节格式验证，并对比 accepted 代数；
  release ID、activation nonce、当前 uploads inode 和 active-release-v4 的完整
  语义绑定仍由同步 receiver 与 FPM guard 失败关闭验证，本版不宣称
  在健康 JSON 中重复整条激活证明链。
- 缺失、超长、零代数、非小写十六进制或任一字段长度错误都失败关闭，
  不会被认为已提交。
- 部署器的旧运行时信任锚前移到已上线的 Build 42.5，新运行时信任锚
  前移到本修复；App Content 信任锚前移到 Build 42.8 模块化清单。
- 状态 schema、systemd service/timer、快照定时器、私有日志配置与页面内容均
  不变。

## 发布顺序

代码标签不等于生产部署。生产执行前必须先确认当前整站同步事务已
成功结束，然后严格按 Build 42.8 将模块化 App Content 先发布到备节点
`standby`、再发布到上海节点 `authority`。两节点都通过清单和路由验收后，
才允许用同样的备节点优先顺序部署本健康运行时。

本版不修改 DNS、CDN、故障转移、同步代数、账号、用户数据或凭据，
不包含 SSH/签名私钥、云 API 密钥、密码、手机号或会话令牌。
