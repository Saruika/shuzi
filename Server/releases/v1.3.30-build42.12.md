# Hi，梳子 1.3.30 / Build 42.12 同步传输重连修复

该记录随 Git 标签 `v1.3.30-build42.12` 保存。本版修复上海 authority
与新加坡 standby 之间的签名同步在短时间建立多个 SSH 会话时偶发
`Connection refused` 的问题，不改变同步协议、签名密钥、远端强制命令、
媒体、数据库或 generation 计数。

## 根因与生产防护

- 新加坡节点原有的通用 `UFW LIMIT 22/tcp` 会在约 30 秒内的第六个新建
  连接开始拒绝；一次正常签名同步包含多次独立的 attestation、protocol、
  ingest 与 receipt 查询，因此合法的固定节点流量也会命中限速。
- 生产防火墙在通用限速规则之前加入精确规则：仅允许固定上海主节点
  `101.43.79.80` 访问新加坡节点 TCP/22。其他 IPv4/IPv6 来源仍使用原有
  SSH 限速；SSH 仍要求固定 ED25519 主机公钥、专用公钥身份、强制命令和
  最小 sudoers 白名单。
- 修复后从上海节点连续执行十次真实 receiver attestation，十次均成功且
  输出摘要完全一致；同期内核日志没有新的上海源地址限速拒绝。

## 客户端重连边界

- 发布器和正式 sender 都使用 OpenSSH 原生 `ConnectionAttempts=3` 与
  `ConnectTimeout=10`。该机制只在远端命令尚未开始前重试连接建立，
  不会在 ingest、对账或任何远端命令已经执行后自行重放。
- sender 的总 deadline 从 45 秒调整为 60 秒，为三次有界建连和成功后的
  固定只读查询留出时间；超时后仍向整个 SSH 进程组发送 TERM，并在五秒后
  KILL，不会留下后台子进程。
- 主机公钥不匹配、认证失败、签名/协议/回执不匹配、远端非零退出与超长或
  非规范输出仍立即失败关闭，不能被重连掩盖。

1. `sync-release-deployer-contract-test.py`、`sync-scheduler-contract-test.py`
   与 `sync-receipt-recovery-contract-test.py` 必须全部通过；完整
   `Scripts/security-check.sh` 也必须通过。
2. 保留已提交且已对账的 generation 7，停止并禁用同步 timer；按
   standby-first 顺序重新发布冻结候选，再将 standby receipt 原字节交给
   authority 发布器。
3. 两节点确认 accepted、active、committed 与 issued 均为 7，确认没有
   incoming transaction 或 sender job 后，使用既有 timer stamp 分别 enable、
   start timer；不得使用 `enable --now`。
4. 连续连接验证和下一次定时同步均不得出现 `UFW LIMIT BLOCK`、回执歧义、
   generation 重用或重复远端执行。
