- 前置检查成功且任务未取消时，iPad 和 Release 分别继续采集结果，即使前面的原生测试失败。
  不使用 `continue-on-error`，原始失败仍使整个工作流失败，不自动重试。
  保留 180 分钟上限、串行运行和用户的每月 USD 20 预算设置；本轮没有触发付费云端运行。
- 在工作流摘要显示每个阶段的实际 outcome、每个完整 xcresult 的通过/失败/跳过数量，
  并区分 Xcode 用例计数和设备/参数化执行次数。不将首次通知授权与完整矩阵混称为全量通过。
- 仅展示静态 Swift 失败用例标识，不复制断言正文、账号值、设备名、截图内容或原始异常。
  缺失/未完成/格式不匹配的结果不会报告为零失败；步骤成功却缺少首次授权或完整矩阵结果包会报错。
- 保留既有失败诊断附件和日志。摘要不修复、重写或删除任何原始结果包。

行为依据：[GitHub 状态条件](https://docs.github.com/en/actions/reference/workflows-and-actions/expressions#status-check-functions)
与 [任务摘要](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-commands#adding-a-job-summary)。
