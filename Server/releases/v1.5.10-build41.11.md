# App Content API 1.5.10 / Build 41.11 健康监控安装器发布记录

该记录随 Git 标签 `v1.3.29-build41.11` 保存。Build 41.10 在备用节点以
`PHASE=LOCKED` 安全拒绝，未创建 Build 41.10 事务目录，也未修改 service、
timer、status 或最终 runtime。只读复验定位到旧 timer 为 `active/elapsed`：
恢复时的 `reset-failed` 使 service 从 failed 转为 dead；在没有 active unit
引用时，systemd 随后可回收并卸载它，旧的激活时间也随之消失。之后使用
`OnBootSec` 重新启动 timer，没有得到新的未来触发点。

Build 41.11 把首个触发器改为 `OnActiveSec=2min`，保留
`OnUnitActiveSec=5min`，因此每次 timer 激活后都能获得确定的未来排程。安装器
先在 disabled 状态启动 timer，使 active timer 引用并固定 service unit，再执行
或验收新的 health invocation，避免成功 oneshot 被 systemd 垃圾回收后丢失
InvocationID、Result 和原始时间戳。旧运行态预检必须连续两次通过；若恰逢
周期触发，只进行有限等待，不放宽任何哈希、角色、systemd 或文件信任门禁。

回滚恢复旧 `OnBootSec` timer 后会显式运行一次旧 health service，以重新建立
`OnUnitActiveSec` 的五分钟排程；随后仍需通过双采样 60–360 秒窗口、旧运行时
哈希、enable 链接、status 持久化和 `ROLLED_BACK` 提交检查。

## 生产启动门禁

不得直接执行仓库副本。先把标签中的安装器原子安装到
`/run/deploy-shuzijun-health-build41.11`，设为 `root:root 0700`、regular、
non-link、nlink=1；三个 runtime 候选分别放入仅含这三项的
`/run/shuzijun-health-build41.11-backup` 和
`/run/shuzijun-health-build41.11-primary`。备用节点必须先成功。

```bash
sudo /usr/bin/env -i PATH=/usr/sbin:/usr/bin:/sbin:/bin LC_ALL=C LANG=C /bin/bash --noprofile --norc -c '
set -Eeuo pipefail
DEPLOYER=/run/deploy-shuzijun-health-build41.11
DEPLOYER_SHA256=7dca0a3324e6bcaa362972f5be0479d4342514d64c72ad44731872a9ef532ea6
[[ ! -L "$DEPLOYER" && -f "$DEPLOYER" ]]
[[ "$(/usr/bin/realpath -e -- "$DEPLOYER")" == "$DEPLOYER" ]]
[[ "$(/usr/bin/stat -c "%F:%u:%g:%a:%h" -- "$DEPLOYER")" == "regular file:0:0:700:1" ]]
[[ "$(/usr/bin/sha256sum -- "$DEPLOYER")" == "$DEPLOYER_SHA256  $DEPLOYER" ]]
exec /bin/bash --noprofile --norc "$DEPLOYER" backup standby
'
```

备用节点完整验收通过后，主节点仅将最后一行替换为：

```bash
exec /bin/bash --noprofile --norc "$DEPLOYER" primary authority
```

## 验收与操作边界

- standby 必须为 schema 2、`role_verified=true`、`critical_reasons=[]`，且只包含
  `standby_failover_state_unhealthy_or_stale`、`standby_failover_timer_disabled`、
  `standby_sync_generation_missing_or_invalid`、`sync_log_generation_missing_or_invalid`。
- authority 必须只包含 `authority_sync_generation_missing_or_invalid`、
  `sync_log_generation_missing_or_invalid`、`sync_timer_missing_or_disabled`。
- 两节点 runtime 与 loaded typed Exec 哈希一致，核心服务 active，固定路由
  全部 `ok=true`，health service 必须以 degraded/exit 2 被 systemd 记为 success。

该事务不运行同步或故障切换，不修改 DNS、CDN、Nginx、PHP-FPM、MySQL、
WordPress 内容或媒体。有效 `DONE` 是提交点；事务前门禁或隔离失败必须
fail-closed，不得误报成功。
