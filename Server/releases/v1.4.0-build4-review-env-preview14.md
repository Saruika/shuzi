# v1.4.0-build4-review-env-preview14

日期：2026-09-07。相册重试按钮的辅助功能命中顺序与连续手势回归。

## 定位证据

preview13 的 iPad 矩阵在双击恢复后的 `缩放 100%` 断言连续失败。本轮保留原断言，添加仅 DEBUG
且显式测试参数启用的手势计数及失败层级附件，再次在 4 个 UI 配置复现：原生缩放仍约 176–183%，
双击识别器计数均为 0；网络失败显示的重试按钮位于测试双击的照片中心。

进一步独立检查故障状态，确认重试按钮虽然位于可见照片范围内，却无法通过辅助功能命中。
原 `accessibilityElements` 把覆盖完整视口的虚拟照片排在实际控件宿主之前，遮住了后者的辅助功能命中。
这不是已经收到双击却不能缩放，也不是单纯把断言等待时间加长就能解决。

## 修复与测试调整

- 真实控件宿主先参与辅助功能命中，虚拟照片后参与；保留缩放值、调整操作、重试按钮及所有视觉布局。
- 手势正常场景显式使用内存生成的 400×600 条纹测试图，仍经过真实图片解码、缓存和渲染路径；
  不依赖可能不可用的远程占位照片，不将“重试按钮上的双击”当作“正常照片上的双击”。
- 故障场景仍强制图片失败，必须能找到当前照片范围内可点击的重试按钮并实际点击；
  然后在无遮挡区域连续三轮捏合、双向拖动、双击恢复，再验证翻页与关闭。
- 两种场景都记录实际窗口几何，测试类结束时必须取得横屏及竖屏证据；保留原来的缩放/页码/关闭断言。
- 测试图、显式开关和诊断计数仅属于 DEBUG；不使用 AI、艺人照片或磁盘图片，不更换 App 正式图片。
