# Hi，梳子 1.3.33 / Build 45.7 推送 Worker 最小读取能力热修复

该记录用于 Git 标签 `v1.3.33-build45.7`。Build 45.6 将 immutable 检查恢复到 root
部署边界后，在与生产完全相同的 capability bounding 下复核发现：密钥文件由
`www-data` 持有且为 `0400`，受限 root 没有 DAC 读取能力时仍不能执行 `lsattr`。
Build 45.6 因此未部署到生产。

本热修仅为 root 校验阶段增加只读的 `CAP_DAC_READ_SEARCH`；`CAP_SETUID` 与
`CAP_SETGID` 仍仅用于随后切换到 `www-data`。生产同构验证确认降权后
Permitted/Effective/Inheritable/Ambient capabilities 均为零，且 `NoNewPrivileges=1`；
实际 WordPress/APNs 投递进程不会继承该读取能力。其余目录、文件、immutable、角色锁、
超时和网络沙箱约束不变。
