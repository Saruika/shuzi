# 媒体写入与注销并发保护候选

2026-09-07（UTC+8）；PHP 1.5.13.12，继承 preview31 保留已发布作品规则和 preview30 相册透明文字层。

## 修复

- 原生 App 内容修改，以及 WordPress REST media/portfolio 写入，在执行回调前取得同一
  publication MySQL 命名锁，再取得操作人既有 per-user 锁，阻止上传、发布、撤权和注销交错。
- 加锁后清除请求内用户/会话缓存并重新鉴权；第一轮权限检查成功，不代表可以在撤权后继续上传。
  Bearer 还必须通过数据库原始会话核验，不接受 get_option 的旧缓存；拒绝时清除当前用户身份。
- App 注销从个人资料清理前一直持锁到 WordPress 删除文件结束；核心删号钩子也共享该锁。
- 冲突返回可重试错误，不忙等；取得部分锁失败时释放已取得的锁，正常、校验失败、权限失败
  均通过 REST 完成钩子释放，shutdown 为异常退出兜底。GET/HEAD/OPTIONS 不参与写锁。
- 不修改 App 页面、文案、相册照片、免费/抖音必填/审批规则，不创建新权限或管理员账号。

## 验证

  写入”断言失败，退出 255；不是因为缺少方法/语法错误而失败。随机测试数据库正常清理。

  断言通过；媒体 103、管理员绑定 242、绑定鉴权 50、并发专项 19 均为总数子集，不应重复相加。
- 并发使用两个独立真实 MySQL 连接，不用单连接可重入锁冒充排他性测试。覆盖上传、建相册、
  改相册和改配置被锁拒绝且无文件/记录变化；锁中仍可读取；注销冲突保留账号；部分锁失败释放。
- 第二连接在首次鉴权之后直接修改测试角色，故意绕过 WP 缓存失效；后续上传正确拒绝。

  未写入图片且两锁释放。数据库错误中止注销后，同样用第二连接确认两锁释放。
