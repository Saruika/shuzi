## GitHub 根因与修复

2026-09-06 登录 GitHub 后，从失败 job 的 Annotations 取得正式原因：
账户付款/支出限制导致 job 未启动。账单进一步确认本月 included minutes 已耗尽，
Actions 超额预算为零且 Stop usage 为 Yes；不能把它描述为测试失败或代码报错。
用户随后明确批准有限月度预算，已保存 Actions 专用预算，保留超额停止与邮件提醒，
未改变其他产品预算、支付方式、仓库可见性或权限。

[轻量 Linux 回归第 2 次尝试](https://github.com/Saruika/shuzi/actions/runs/34006546748)
已实际启动并全部成功，包含 checkout、真实锁争用和 60 秒截止测试。
完整 iOS 云端矩阵仍需在当前提交运行，不把轻量任务通过当成 App 全套通过。

为控制重复开销，main 上只有四类根目录说明文件的变更不自动启动完整 Mac 作业：
README、QA 报告、首页设计说明、上架清单。PR 与手动入口保持全量；源码、
依赖、发布记录、工作流及服务器代码均不在忽略范围。checkout 不再保留 Git 凭据。
所有既有测试、SAST/SCA、SBOM、签名/依赖固定和失败判断保持不变。

本地预检另发现历史同步安装器 `os.fchmod(..., 0o755)` 触发 Bandit B103。
该对象是 root 运行、目录和完整字节哈希已验证的无密钥可执行脚本，不是私人数据；
现有安装/回滚协议要求 0755 且禁止 group/other 写入。保留原行为，只在这一行加
带理由的 B103 复核标记，并新增真实临时文件发布回归，验证精确权限、不可写位、
发布内容和 staging 清理。没有全局关闭 B103，没有修改生产权限或执行生产安装器。

## 合作存储修复与实测

- 在读写功能启用前，逐表验证 InnoDB、全部字段的类型/长度/nullable/default/
  auto_increment，以及全部主键、唯一键、普通索引和字段顺序。
- 拒绝截短索引、隐藏/忽略索引、错误唯一性、未知列/索引、部分元数据及数据库错误。
  仅兼容 MySQL/MariaDB 无语义差异的整数显示宽度，不放宽 unsigned 或长度约束。
- 每次 `dbDelta` 检查返回形状与即时错误，再检查实际元数据；异常和部分成功不写 ready
  版本，迁移锁在 finally 释放。没有自动转换真实表引擎或删改真实记录。
- 独立 PHP 8.3 夹具运行真实 trait 的 486 项元数据/错误断言通过。
- MySQL 8.0.46 临时随机空库 28 项实测通过：建表、错误引擎、缺表、字段变化、缺失/
  错序/截短索引、唯一性拒绝和事务回滚。没有生产数据或真实联系方式；临时库已精确删除。
- 全量既有 PHP 合同、推送所有权/回滚、工作器结果回归在禁止网络且不可访问生产
  WordPress/数据库的 systemd 沙箱通过。首次沙箱禁止写 /tmp 导致夹具初始化失败；
  修正为仅测试临时区可写后原样复跑通过，没有为此修改生产代码或降低产品断言。
- 独立候选 Git 快照的本地完整门禁、Ruff、Bandit（medium 及以上门槛）、供应链和
  发布信任材料合同均通过；本机无 PHP/Composer，不把本机的缺失工具当作已执行，
  PHP 结果来自上述独立 Linux 沙箱。Bandit 的 7 项低级别既有结果未被宣称清零。
- 真实 MySQL 测试使用直接 DDL 夹具，不等同完整 WordPress `dbDelta`、并发双节点、
  邮件和隐私生命周期验收。上述未完成项继续由 Phase 1 门禁阻止上线。
