## 接口及产品边界

- 新增 `PATCH /wp-json/shuzijun/v1/app-admin/fans/{uuid}/administrator`。
  请求必须携带 JSON 布尔值 `administrator`、`expectedAdministrator`，
  以及非负整数 `expectedRevision`。客户端从最新用户资料取得当前状态和修订号。
- 管理端 permission callback 和实际写入 callback 都校验调用者；
  只有具有完整 App 能力的管理员可以授予/撤销身份，不能把局部权限扩大为完整权限。
- 授权要求目标是已审批、抖音 ID 完整、无待完成邀请/密码恢复/Apple 设置的用户；
  Apple 来源还需已有有效隐私同意记录。自我修改禁止，需另一位管理员操作。
- 只绑定 `yishu_content_manager`，不授予 WordPress 整站管理权。
  若共享角色意外包含额外网站能力，停止授予；撤销仍可执行。
  不覆盖目标原有的独立网站权限，不修改其普通相册权限、免费政策或审批状态。
- 用户资料新增 `administratorBound`、`administratorRevision`。这些是展示与并发控制信息，
  不是客户端授权依据；每次管理请求仍必须通过服务端认证。

## 一致性与审计

- 按固定顺序取得绑定操作锁、调用者锁和目标账号锁，清理 WP 用户缓存后重新校验权限及主节点身份。
- 当前状态及单调递增修订号双重比较，防止“授予→撤销”后旧请求再次授予的 ABA 情况。
- 要求用户表/元数据表使用 InnoDB；角色、修订号和审计记录在同一事务内更新。
  重复或异常元数据拒绝写入。审计/修订号失败会回滚已写入的角色。
- 审计只保留最近 50 次变更，记录实际调用者内部 ID、状态、修订号及时间；不保存密码、令牌或邮件内容。
- 撤销后已有 App 会话的下次管理请求被拒绝，仍保留其正常获批的粉丝访问。
- 同状态、同修订号请求不重复写入审计；状态冲突返回 409，客户端必须刷新，不能自动覆盖。
