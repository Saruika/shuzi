## 已封闭的部署缺陷

- 安装器只接受 `primary authority` 或 `backup standby` 两个精确组合，固定
  stage、目标、旧/新 SHA、角色 verifier 与 App 内容 SHA，不再接受任意
  commit 参数。
- `validate_last_invocation` 在 root 主 shell 中运行；每个断言显式传播失败，
  不经过会抑制 Bash `errexit` 的 pipeline/command substitution。status mtime
  和 `checked_at` 绑定最后一次 systemd invocation 的原始 D-Bus wall 微秒窗，
  同时用 monotonic 微秒证明 invocation 位于安装器观察窗内。
- systemd 的 `LastTriggerUSecMonotonic`、`NextElapseUSecMonotonic` 和 service
  执行时间全部从 typed D-Bus uint64 读取，不解析 `systemctl show` 的人类可读
  时长文本。
- timer 的 Job、InvocationID、trigger 和下一次触发连续采样；下一次触发只
  接受 60–360 秒范围。若 start/enable 窗口发生一次或多次真实调度，最后一次
  invocation 与新 status 必须按完整角色、reason、critical、服务、路由和
  App 哈希契约重新验收。
- 旧 timer 仍 active 的最早门禁同时固定 PID 1 已加载的 Exec、空辅助 Exec、
  `NeedDaemonReload=no`、timer Unit、Job 与精确 idle/failed 结果；磁盘字节虽已
  恢复但尚未 daemon-reload 的旧配置不能越过 `PREPARED` 前门禁。
- Exec 不再依赖 `systemctl show` 的扁平字符串，而是逐元素比对 typed D-Bus
  `ExecStartEx` 的 path、argv 和空 flags；同时固定 root user/group、空
  `Environment*`、空 root/working directory 及空执行搜索路径，阻断参数边界和
  加载执行上下文漂移。
- 备份副本同时绑定固定 SHA、mode 和冻结后的源文件；journal 写入的每一步
  都显式返回失败。`DONE` 与 `ROLLED_BACK` 使用 O_NOFOLLOW、fd/path inode、
  metadata 和精确内容复验，消除了终态信号竞态与“回滚失败却声称成功”。
- timer enable 链接目录允许在 disabled 阶段被 systemd 安全删除；存在时必须
  是 canonical、root-owned、不可由非 root 写入的实目录。enabled 阶段要求
  `shuzijun-internal-health.timer` 是 root 所有、nlink=1、绝对指向固定 unit 的
  symlink。链接目录及其父目录、status 文件系统、备份和 journal 均在终态前
  fsync/syncfs 并复验。
- 仅对从未允许 group/other 写入的 root-owned 日志原 inode 收紧到 0600；
  历史可写日志保持不可信，避免旧伪造内容因 chmod 被追溯“洗白”。它继续产生
  degraded reason，直到后续由受信 writer 安全轮换。

## 生产启动门禁

不得直接执行仓库副本，也不得从 `/private/tmp` 或其他可写路径启动。先从本
Git 标签取安装器，原子安装到 `/run/deploy-shuzijun-health-build41.8`，设为
`root:root 0700`、regular、non-link、nlink=1；三个 runtime 候选分别放到
`/run/shuzijun-health-build41.8-backup` 和
`/run/shuzijun-health-build41.8-primary`，每个目录只允许三项固定文件。

Bash 会在脚本第一行之前读取 `BASH_ENV`。因此外部 SHA/metadata 校验与 exec
必须在同一个 clean-env root shell 中完成。备用节点先执行：

```bash
sudo /usr/bin/env -i PATH=/usr/sbin:/usr/bin:/sbin:/bin LC_ALL=C LANG=C /bin/bash --noprofile --norc -c '
set -Eeuo pipefail
DEPLOYER=/run/deploy-shuzijun-health-build41.8
DEPLOYER_SHA256=9d603a7524af6d6c04ee4e2b7dd06883d3af4ad9c38ff55c5fddf07229be9021
[[ ! -L "$DEPLOYER" && -f "$DEPLOYER" ]]
[[ "$(/usr/bin/realpath -e -- "$DEPLOYER")" == "$DEPLOYER" ]]
[[ "$(/usr/bin/stat -c "%F:%u:%g:%a:%h" -- "$DEPLOYER")" == "regular file:0:0:700:1" ]]
[[ "$(/usr/bin/sha256sum -- "$DEPLOYER")" == "$DEPLOYER_SHA256  $DEPLOYER" ]]
exec /bin/bash --noprofile --norc "$DEPLOYER" backup standby
'
```

备用节点事务和只读验收全部通过后，主节点使用相同校验，只把 exec 行改为：

```bash
exec /bin/bash --noprofile --norc "$DEPLOYER" primary authority
```

任何外部 SHA/metadata 校验失败、安装器回滚、CRITICAL、非预期 reason 或节点
差异都会停止后续节点。固定执行顺序不可颠倒。

## 精确上线验收

上海 authority 必须为 `schema=2`、`role_verified=true`、
`status=degraded`、systemd `Result=success`、`ExecMainStatus=2`、
`critical_reasons=[]`，且 `operation_reasons` 精确为：

- `authority_sync_generation_missing_or_invalid`
- `sync_log_generation_missing_or_invalid`
- `sync_timer_missing_or_disabled`

新加坡 standby 的共同字段相同，`operation_reasons` 精确为：

- `standby_failover_state_unhealthy_or_stale`
- `standby_failover_timer_disabled`
- `standby_sync_generation_missing_or_invalid`
- `sync_log_generation_missing_or_invalid`

两个节点还必须保持全部核心服务 active、全部固定路由 `ok=true`，且 status 中
App manifest/PHP 哈希等于本记录的固定值。degraded 是对尚未授权执行的同步/
故障切换前置条件的如实报告，不是业务不可用。

## 回滚与操作边界

安装器只会启停 `shuzijun-internal-health.service/.timer`、执行全局
`daemon-reload`、写自身 status/事务备份/journal，并对原本可信的两类固定日志
收紧 metadata。它不会运行数据库或媒体同步，不会启用 failover，不会修改
DNS、CDN、Nginx、PHP-FPM、MySQL、WordPress 内容或 App 媒体。

失败回滚必须先证明 health timer/service 已隔离；只有固定旧备份、status、
systemd unit、enable 链接、后续 timer 稳定性和 `ROLLED_BACK` journal 全部通过
才报告 verified rollback。有效且精确匹配的 `DONE` 是提交点；其后信号不会
反向回滚。SIGKILL 或掉电无法由 shell trap 捕获，人工恢复应读取 root-only
事务目录的最后一个有效 marker，并按 Build 41.7/41.8 记录恢复，不得猜测状态。
