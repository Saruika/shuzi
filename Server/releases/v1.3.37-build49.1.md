# v1.3.37-build49.1 — 相册缩放渲染优化（源码补丁）

本补丁针对打开相册照片后双指放大、尤其放大后拖动必现卡顿的反馈。不改变页面外观、图片比例、4 倍缩放上限、翻页、关闭或图片保护策略；不添加本地照片文件或磁盘图片缓存。

## 调整

- 将 SwiftUI 每个手势事件更新 scale/offset 的实现替换为 UIKit pinch 手势 + UIScrollView。缩放通过 UIKit API 显式更新，并保持手指下的图片位置；连续拖动由 UIScrollView 处理。UIHostingController 内的图片仅在图片或视口变化时更新，不在滚动回调中更新 SwiftUI 状态。
- 1 倍时内层 pan 不开始，让外层相册处理翻页；放大后由内层滚动处理拖动。不在手势执行中反复启停内建 recognizer。双击恢复、辅助功能缩放、加载重试入口和旋转后恢复完整构图均保留。
- 为渐进式图片内容增加 Equatable 边界。图片 URL、内容或窗口尺寸变化仍正常刷新，内部异步加载状态不被屏蔽。
- 以图片加载器的 phase 为唯一就绪状态：高清图就绪前/失败时显示预览，成功后替换成高清图，避免两层图片持续参与缩放合成和重复的就绪状态。
- 图片解码继续使用已有后台降采样管线，不新增主线程解码、额外下载或图片持久化。

## 验证

- Debug 模拟器构建通过；168 项单元测试通过，包含图片内容/尺寸变化使渲染边界失效，以及原生滚动连续 100 次位移不重新提交图片内容、视口变化重置缩放的新增测试。
- 最终 UI 用例通过：iPhone 17 Pro Max 四组、iPad Pro 13-inch (M5) 四组配置，均完成三轮双指放大、双向拖动、双击恢复，再翻页、关闭；测试未传入关闭图片保护的参数。早期仅双指缩放的 8 组通过结果不作为最终实现的验收。
- 初次复用模拟器时发生 Mach/FBS 启动失败，未将该次失败作为通过；改用本次独立创建的测试模拟器重跑。
- 中间候选的 iPad 内建 pinch 回调记录到了约 1.8 的手势比例，但最终 zoomScale 仍为 1，UI 测试失败。最终方案显式调用 UIKit 缩放，不依赖该中间候选的行为；失败记录保留，不算通过。
- 跨机型复用 iPad thinned 编译产物时，iPhone 两项社交图标像素检查失败。actool 日志显示资源按 iPad17,4-B 裁剪；独立 iPhone18,2 构建后 168 项单元测试全部通过，未修改或放宽图标检查。

最终证据：`/tmp/yishu-gallery-zoom.Smr1ei/Final-iPad.xcresult`（4 项 UI 通过）、`Final-iPhone.xcresult`（4 项 UI 通过；含上述跨设备资源复用造成的 2 项单元失败）、`Final-Phone-Unit.xcresult`（独立 iPhone 构建，168 项单元全部通过）。未把含失败的整份结果包标成成功。

代码显示原实现会在连续手势期间反复更新 SwiftUI 状态，并存在双层图片合成，但这不等同于已用 Instruments 证明用户真机掉帧的全部根因。此补丁没有真机前后 FPS/掉帧对比，不承诺所有机型零卡顿。UI 测试采用固定多图回归数据，不代表全库高清原图或弱网性能测试。
