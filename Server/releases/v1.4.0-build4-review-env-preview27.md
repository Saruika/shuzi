# 修正审核相册链接并通过真实原生管理员流程

版本记录：`v1.4.0-build4-review-env-preview27`，2026-09-07（UTC+8）。

## 根因与修复

preview26 的原生联调在读取管理内容时失败。独立 WordPress 默认 `permalink_structure`
为空，两个相册 websiteURL 的 path 都是 `/`，而生产 Swift 既有策略要求 `/portfolio/`。
原先 HTTPS 验收只检查图片 URL，未覆盖相册 websiteURL，因而漏掉该问题。

在真实 WordPress 的 CLI 内存中模拟正确选项并重新注册同样的非公开 CPT 后，两条路径
均变为 `/portfolio/…/`，`publicly_queryable` 仍为 false；该模拟没有写入数据库。
期间一次直接对旧 CPT 对象调用 add_rewrite_rules 的只读试验遇到未规范化的布尔 rewrite
参数而退出；只影响该 CLI 进程，没有改服务/选项，改为真实重新注册的流程后模拟通过。

- 新修复工具默认只读，应用前核对固定 review 路径、数据库、域名及空旧结构，保存私有元数据记录。
  只设置 `permalink_structure=/%postname%/`，新 WordPress 请求生成相册链接，核对目录内容摘要不变。
  不改作品、账号、密码、nginx、公开访问设置或其他站点；不执行硬重写/服务重启。
- 已有其他非空结构拒绝覆盖；预检后发生外部变化不自动回滚别人的更改；本次失败只恢复已知状态。
- bootstrap 初始化新增相同配置，HTTPS 目录验收新增 websiteURL 的域名、路径和查询限制。
  不放宽 Swift URL 规则，不通过造假清单或补造视频取得通过。
