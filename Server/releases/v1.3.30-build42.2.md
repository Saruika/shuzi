# Hi，梳子 1.3.30 / Build 42.2 健康发布门禁修复

Build 42.2 取代 Build 42.1 作为生产部署候选。签名同步核心字节不变，
仅修复健康监控事务发布器在真实 systemd 上暴露的旧单元属性断言。

## 生产预检发现

新加坡第一次运行在任何备份或服务变更前以退出码 1 失败关闭。
已核对：旧监控脚本、service、timer 和 status 均未改变，健康 timer 仍为
enabled/active，快照锁已释放，未生成新事务备份。

原因是发布器同时固定了旧 service 文件 SHA-256，却又错误要求其
systemd `SuccessExitStatus` 为空。该旧文件一直明确配置
`SuccessExitStatus=2`，且生产回读为 `2`。两个条件自相矛盾，使候选无法进入
变更阶段。

## 修复

- 旧单元门禁现在精确要求 `SuccessExitStatus=2`，与已固定旧 service 一致。
- 合同 fixture 的正常路径真实返回 `2`，新增错误值 `0` 的负向测试。
- 健康发布器的固定路径、stage、事务备份名与 release ID 升级为
  `build42.2`，避免复用已失败候选的临时输入。
- 生产 `/run` 为 `noexec`，所以保留固定 `$0` 与 root-only 元数据检查，
  并由固定系统解释器执行：健康发布器用 `/bin/bash`，同步发布器用
  `/usr/bin/python3 -I`。
