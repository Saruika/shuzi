# 系统允许通知后自动启用（本地候选）

2026-09-14；基于 `afbfac7`。用户确认：系统弹窗选择允许后，不再要求去 App 账号页
手动打开通知。App 仍为 `1.4.0 (6)`，没有覆盖审核中的安装包；正式打包时需新构建号。

## 原因与调整

旧代码要求存在一次性启动授权标记，且只允许一个账号消费。标记缺失、老安装已经取得
系统权限，或切换账号后，即使系统仍为允许，App 开关也可能保持关闭。

- 当前账号完成登录与必填资料、处于待审批或已通过状态，系统状态为 `.authorized`
  且没有该账号主动关闭记录时，自动开启并调用 APNs 设备登记，收到令牌后经当前会话绑定。
  不再依赖旧启动标记，也不要求第二次手动开关。
- 尚未决定、拒绝、静默临时授权不作为自动开启依据。未登录、资料不全、暂停/拒绝、
  过期会话或不可用的 Apple 凭据不开放绑定。系统撤销权限后停止本机接收并尝试解绑。
- 开关选择改为本机按环境与账号哈希保存，迁移旧关联记录及无法归属具体账号的旧关闭记录。
  A 关闭后切换 B、B 自动开启、再返回 A，仍保留 A 的关闭；不沿用 A 的连接或消息。
- 只有服务器确认账号删除后才移除对应本机开关偏好；删除结果未知时保留关闭选择，
  迟到的旧账号删除响应不影响当前另一账号或其他环境。
- 保留现有有限次数重试，已验证自动开启后的绑定网络失败可自行恢复。账号页说明与
  App/官网政策模板同步，不改变数据用途、政策同意版本、页面布局、截图保护或后台权限。

`security-check: passed`，进程退出 0。
不修改或放宽该夹具，不将初次失败抹除。PHP/Composer 未安装，对应可选分支未执行；
Linux flock 等环境相关跳过不能算运行验证通过。

首次通知 UI 使用已有 Debug 专用测试方式，不更改正式保护；没有真实用户账号或 APNs
实收验证，不能用模拟器结果保证通知必达、立即到达或后台投递百分之百成功。
测试专用模拟器 `7DCE9985-93BD-4176-BA6E-74D0616EE56A` 已删除，结果日志保留。
