# Build 46.3：推送队列调度提速

客户端仍为 TestFlight `1.3.34 (46)`，插件仍为 `1.5.12.3`。
本次只发布推送工作器的调度配置与受控升级工具，不改变 App、页面或消息正文。
Git 标签：`v1.3.34-build46.3`。

## 问题和调整

此前两条实际通知在创建约 30/31 秒后被 APNs 接受，其中约 26 秒为等待工作器启动。
原定时器每分钟运行，另外允许 5 秒调度精度窗口。

- 调整为工作器结束后 5 秒再次调度，精度窗口 1 秒。
- 不按固定间隔并发启动：耗时任务完成后再计时，保留单工作器、角色及租约保护。
- 仅上海主节点启用定时器；备用节点安装相同资产但保持禁用。
- 升级工具只允许精确旧版/新版定时器哈希，其余工作器、服务和 FPM 资产必须完全匹配。
- 升级不重启 PHP-FPM，不中止在途工作器；失败恢复旧定时器，重复安装不重置服务。

这缩短的是服务器排队时间，不是“保证 5 秒到手机”。APNs 接受不等于用户收到横幅；
网络、设备、通知权限、专注模式和 Apple 调度仍会影响展示。
只收云消息箱与客户端自动恢复将单独发布，不包含在本版本中。

## 测试及部署结果（2026-09-05）

- 运行器配置合同、精确旧版升级、未知哈希拒绝、失败回滚、重复安装等测试通过。
- 上海节点使用隔离的随机临时 systemd 单元，运行三轮每轮 7 秒的慢任务；
  前次结束到下次开始为 5.999/6.006 秒，无重叠，临时单元已清理。
  测试不调用实际推送、WordPress 或数据库。
- 两节点按 backup/standby → primary/authority 完成 dry-run、安装、状态验证。
- 主节点读取到 `OnUnitInactiveUSec=5s`、`AccuracyUSec=1s`、active/enabled；
  备用节点状态验证通过且保持禁用。工作器退出码为 0，PHP-FPM 持续运行。
- 上线后空队列单次工作器 CPU 时间约 0.46 秒；该提速会增加空队列检查频率，
  需要持续关注资源使用，不将空队列检查描述为真实推送到达测试。
- 本次没有向真实用户发送测试消息。

## 尚未涵盖

现有 WP-CLI cron 调用不会自动把 hook 返回的 `false` 转为进程失败；因此服务退出 0
仅证明调用完成，不能代替逐条 outbox 状态或存储健康检查。该可观测性问题应单独修复。
APNs 已接受的消息不应因为未读而重复推送，避免重复打扰。
