# Build 47：只收云消息箱与推送可靠性

App `1.3.35 (47)` 已可进行 TestFlight 内部测试，App Content API `1.5.13` 已部署两节点。
实际测试、部署及 Apple 处理状态如下；尚未提交正式 App Store 审核。

## 功能范围

- 账号页增加“消息箱”。粉丝只能查看自己的消息及标记已读，无发送、回复、私聊入口或接口。
- 完成必填资料的有效 pending/active 账号可读；没有推送设备或关闭系统通知不影响云消息。
- 只有既有推送权限的管理员可发送；消息先持久保存云端，系统提醒走独立 outbox。
- 敏感消息原文不再被通用提醒覆盖；仅在构造 APNs payload 时脱敏，携带消息 UUID，
  点击后通过当前账号认证重新获取内容。旧敏感消息已丢失的原文无法恢复。
- 消息、收件关系及已读状态最多保留 30 天，读取不延长期限；删除账号清理本人关联，
  共享消息继续保留给其他收件人，失去全部收件人后删除原文。
- App 消息只在内存中保留，退出/换号清空，迟到响应不可污染新账号。
- 不改变首页、相册或播放器布局，不恢复社区或订阅。

## 可靠性修复

- 客户端注册/绑定失败使用 5、15、60、300、300 秒有限重试；成功、退出、换号或关闭
  通知取消旧任务，401 要求重新登录。不会重置既有用户的通知偏好。
- 退出登录不再等待网络才清理本机：先同步清会话、消息和请求代际，再使用旧凭据及
  绑定代际快照尽力解绑/注销。弱网或旧请求迟到/401 不得清掉之后登录的新账号。
  新增两个确定性内存回归与接入 CI 的本地源码接线合同；没有加入 Release 鉴权旁路。
- 定时器提速已独立发布为 `v1.3.34-build46.3`：上海节点在上次工作完成后 5 秒调度。
- 每条清理 SQL 独立检查失败，不让后续成功清掉错误。WP-CLI hook 将失败/异常转换为
  固定无敏感信息的失败状态，避免进程退出 0 掩盖不可用；逐任务结果区分已处理与已展示。
- 已持久化重试/终止不误报为整体失败；事务写回、提交和调度失败仍如实上报。
- 失效设备的批量终止不再清掉当前任务仍需用于完成写回的租约，修复失效令牌清理回滚。
- APNs 接受不是手机已展示或用户已读，不因为未读重复推送，不承诺系统横幅百分之百送达。

## 接口及迁移

```text
GET  /fan/notifications?limit=20&cursor=<nextCursor>
GET  /fan/notifications/{notificationID}
POST /fan/notifications/{notificationID}/read
```

全部使用正常粉丝会话、安装记录、数据库新鲜身份及本人收件关系；403/401 失败关闭，
其他人的消息、不存在及过期消息统一 404。GET 无隐式已读写入；POST 已读幂等。
分页按降序内部 ID，limit 1–50，认证响应 no-store。
Schema 4 仅为 recipients 增加 nullable `read_at` 和查询索引，不删除旧消息或设备数据。
回滚旧代码时保留附加列；不通过降级迁移删除新数据。
