## 云端证据与根因

- 新运行 [#134](https://github.com/Saruika/shuzi/actions/runs/34065839296) 使用 011d690，
  已通过工具链来源、文件指纹契约、Ruff、Bandit、SBOM、Python 与 Composer 依赖审计。
  因此 preview19 处理的两项前置问题已得到真实云端验证。
- 随后的仓库检查在 PHP `collaboration-private-payload-test.php` 的“合法文件加载”断言失败。
  测试直接使用 `sys_get_temp_dir()` 构建路径；macOS 系统临时目录可能含软链接祖先，
  而生产加载器要求配置路径严格等于规范路径，正确地拒绝了这个正向测试夹具。
- 在独立 Linux 临时测试源码目录，给旧测试设置含软链接的 TMPDIR，实际 PHP 8.3.6
  复现相同异常和退出 255。不读取 WordPress 站点配置或真实密钥，不连接数据库或发邮件。

- 正向夹具先解析临时目录的 `realpath`，检查它存在，并检查随机 0700 目录创建成功。

- 增加“祖先目录是软链接，即使目标私有、密钥正确仍拒绝”的断言，避免放宽检查。
- 新测试在普通 TMPDIR 和软链接 TMPDIR 下均为 **543 项断言通过**。

  插件契约（含推送所有权和 worker 结果）、五种环境 117 项、schema 444 项及
  实际发布熔断探针均通过。所有源码位于独立临时目录，只使用合成数据与测试替身；
  不把 Linux PHP 验证说成已经获得修正后的 macOS 云端完整通过。
