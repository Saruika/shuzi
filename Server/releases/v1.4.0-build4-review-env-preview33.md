## 原生测试条件诊断

- 在新建自有 iPhone 17 Pro Max / iOS 26.5 模拟器运行 shipping stores 的 opt-in 测试，
  未跳过注册审批或以模拟服务器响应代替真实 HTTPS。
- 前两轮在注册后不能建立本地会话。第三轮加入前置钥匙串探针，实际返回 `-34018`；
  本机 SDK 将其定义为 `errSecMissingEntitlement`。测试构建使用 `CODE_SIGNING_ALLOWED=NO`，
  缺少所需签名权限，不能把这些结果归因为生产注册接口 503。
- 启用模拟器 ad-hoc 签名后，旧文稿目录中的构建产物又被 codesign 拒绝：
  `resource fork, Finder information, or similar detritus not allowed`；实际包目录存在
  `com.apple.FinderInfo` 和 File Provider 属性。已将本轮构建移到用户 Library 下标准 DerivedData，
  保留旧产物和失败结果，没有关闭签名或清理整个用户缓存。
- 测试新增真实 device-only Keychain 写入/删除前置检查，以及仅输出白名单类别的注册失败诊断。
  不打印服务响应、密码、HS 身份码、用户 ID 或令牌；不改变生产认证代码。
- 每次失败都撤销该轮一次性管理访问码，清理精确随机标记匹配的测试账号和合成媒体，
  对比原用户/文章 ID 集合与内容配置摘要一致，并删除本轮自有模拟器。最终审核账号未重设。
