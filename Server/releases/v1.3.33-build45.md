# Hi，梳子 1.3.33 / Build 45 与 App Content API 1.5.12 发布记录

该记录用于 Git 标签 `v1.3.33-build45`。本版在不改变现有内容清单与相册展示规则的
前提下，加入“管理员向指定粉丝发送通知”的完整候选链路。该链路必须由登录粉丝主动
授予系统通知权限并登记设备；管理员只能按单个用户 UUID、身份码或明确用户列表发送，
不能向未选定的全体用户广播。

本记录描述的是尚未部署的 GitHub / TestFlight 候选。代码库不包含 APNs 私钥、
服务器数据加密密钥、设备令牌或任何真实账号凭据；Xcode 项目依 Apple 要求保留公开的签名团队元数据。
本记录也不代表生产推送已经上线。

## 同意版本零中断过渡

App Content API 1.5.12 是 Build 42 到 Build 45 的受审过渡服务器。当前政策版本仍为
`2026-09-04-approval-v4`，Build 45 的所有新确认只提交 v4；为了避免升级顺序导致新注册
中断，1.5.12 的新注册、Apple 首次资料或存量资料补全、一次性邀请完成入口会临时且精确
接受以下两个字符串，并保存客户端实际提交的原版本：

```text
2026-09-02-approval-v3
2026-09-04-approval-v4
```

缺失、非字符串、v2 或任何未知版本仍失败关闭。已存的合法 v2、v3、v4 记录继续有效，
不会要求现有账号重新确认。该双接受列表写死在 1.5.12 源码和合同测试中，不提供环境变量、
WordPress option、过滤器或远程开关。Build 42 过期且确认不再产生 v3 新请求后，必须发布
服务端 1.5.13，移除“新提交 v3”兼容；1.5.13 仍应保留已存 v2/v3/v4 记录的登录连续性。
该桥接只解决同意版本协商，不放宽“抖音 ID 必填”：Build 42 界面虽仍标为选填，向 1.5.12
提交新申请时也必须填写合法抖音 ID，否则按现行账号政策失败关闭。

## 功能与权限边界

- 登录粉丝通过受 Bearer 会话和当前安装记录双重约束的接口登记或解绑 APNs 设备令牌。
  令牌按 Apple 的不透明、可变长度二进制标识处理，不假定固定为 32 字节。
- 管理端按昵称、身份码或抖音 ID 远程搜索用户；结果采用服务器分页，旧用户不会因最近
  用户数量超过一页而无法选择。
- 定向发送接口要求独立的 `manage_yishu_push_notifications` capability。内容管理员和
  WordPress 管理员会获得该权限，其他已认证角色缺少权限时返回明确的 403，不扩大内容
  发布或粉丝审批权限。
- 每次发送必须提供 1–100 个明确收件人和幂等键。服务端保存通知、收件人关系和逐设备
  Outbox；短暂错误有界重试，APNs 返回失效令牌时立即移除对应设备绑定。
- APNs 绝对过期时间由服务端在通知创建时固定为 24 小时，客户端不能传入或延长；离线设备在
  该窗口内恢复网络时仍可收到提醒，超过窗口后不再由 Apple 保留。
- 通知默认按敏感内容处理，锁屏标题与正文降级为“Hi，梳子 / 有新消息，请登录查看”。
  只有管理员明确声明正文可公开时，才使用经长度限制和净化后的自定义文字。
- 退出、撤销会话、修改或恢复密码、拒绝或暂停账号以及永久删号都会清除相应设备绑定；
  Worker 在实际投递前再次核验账号状态、安装记录和正常会话，避免清理失败后的误投。

## 数据保护与保留

- 设备令牌使用 libsodium Secretbox 加密保存，并以独立 HKDF 派生密钥生成 HMAC 索引；
  新密文同时保存一个不可逆、非秘密的 `keyFingerprint` 数据密钥指纹，用于识别主备节点密钥配置错误；
  数据库、错误码和审计日志均不保存或输出令牌明文或数据密钥。
- 在数据密钥缺失、临时不可读、加密依赖不可用或密钥指纹不匹配时，Worker 会保留设备
  绑定，将任务以 `device_crypto_unavailable` 退回 pending，60 秒后重试且不消耗当次
  投递次数。只有在当前密钥已验证可用的前提下，密文结构、Secretbox 认证或 HMAC
  校验失败才会清理设备并终止该任务。
- 安装记录和令牌索引均为全局唯一，权威数据库持久保留当前会话所有权、单调绑定代次和期望状态。换号登录会把同一安装原子转移至当前账号，不保留
  跨账号残留。单个账号最多保留 16 个有效设备。
- 设备绑定最长保留 90 天；通知正文、收件人关系和 Outbox 最长保留 30 天。永久删号会
  同步清除该用户的绑定、待投递任务、收件关系及不再有收件人的通知正文。
- APNs Provider JWT 在进程内复用，并以数据密钥派生的另一把 Secretbox 密钥加密后做
  约 50 分钟的跨请求缓存；命名锁防止并发请求频繁重签。缓存中不保存明文 JWT。

## 生产配置（仅名称，不含取值）

PHP-FPM 运行环境必须提供以下配置；所有文件均须位于仓库和 Web 根目录之外，使用独立
服务账号读取，权限不得宽于 `0600`，且不得使用符号链接或多硬链接：

```text
YISHU_APNS_KEY_ID
YISHU_APNS_TEAM_ID
YISHU_APNS_PRIVATE_KEY_PATH
YISHU_APNS_DATA_KEY_PATH
```

服务端固定使用生产 APNs `https://api.push.apple.com`，topic 固定并校验为
`cn.com.shuzijun.yishu`。主、备节点必须配置相同的 `YISHU_APNS_DATA_KEY_PATH` 内容，
否则切换后无法解密已有设备令牌；`.p8`、Key ID 与 Team ID 也必须分别在两台主机的安全
   环境中可用。只有当前上海 authority 节点可以建表、调度和消费 Outbox，standby 不得并行
发送。

## 部署与真机验收前置条件

1. 为服务端 1.5.12 重新生成并审核哈希校验发布清单；按 standby 先、authority 后执行既有
   dry-run/apply 流程，禁止手工覆盖生产插件或在整站同步事务中部署。
2. 在两台节点安全放置同一数据密钥和已授权的 APNs `.p8`，确认 PHP-FPM 可读取后再重启
   服务；验证五张推送表（含持久安装所有权表）的列、唯一索引、TTL 和迁移中断后的失败关闭行为。数据密钥轮换时必须
   先停止 authority Worker，完成全部设备密文的受审重加密后再切换；不得直接替换数据密钥文件。
3. 保证 authority 的 WP-Cron 或受管系统定时器持续运行，验证 standby 不消费任务；再演练
   authority 切换、处理中租约回收和重复投递窗口。APNs 已接受但数据库状态写回失败时采用
   at-least-once 语义，`apns-collapse-id` 只能缓解、不能绝对消除重复提醒。
4. 使用 TestFlight 真机验证首次授权、拒绝授权后重试、令牌更新、单用户与明确多用户发送、
   多设备、离线后 24 小时保留窗口、退出、撤销其他会话、拒绝/暂停账号、删号、
   410/BadDeviceToken 清理及 408/429/5xx 重试；另外注入数据密钥文件短暂不可读、加密依赖
   不可用与主备密钥指纹不一致故障，确认设备不被删除、Outbox 尝试次数不增长且 60 秒后
   可恢复。不得用模拟器结果代替生产 APNs 端到端验收。
5. 在 App Store Connect 隐私标签、App 内政策和公网政策中如实披露通知设备标识、用途、
   处理方、保留期限、关闭通知与删号路径。所有验收通过前，能力接口和发布说明不得把推送
   表述为“已上线”或“必达”。
