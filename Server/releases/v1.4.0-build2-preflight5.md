# 删号合作数据事务保护

版本记录：`v1.4.0-build2-preflight5`，2026-09-06。服务端候选 **1.5.13.3**，仍保持合作功能生产硬关闭。没有部署、操作真实用户、发送邮件或上传 TestFlight。

## 真实复现与修正

旧清理方法只检查三张表存在，不核验事务能力。在独立 WordPress 7.1 / MySQL 8.0.46 测试库把合成 audit 表改为 MyISAM，原方法仍开始删除并返回成功，实际触发断言失败 `non-transactional deletion must fail before partial erasure`。MyISAM 不提供所需回滚保证，不能把 START TRANSACTION 当成完整保护。

候选在任何删除前核对完整物理 schema、InnoDB 和索引；异常时返回已有清理失败结果，并仅记录固定错误码。这里不依赖功能开关或 ready option，因此关闭功能、缺失/损坏 option 都不妨碍兼容历史表的数据清理。三表均不存在仍正常视为无历史数据；部分表存在仍拒绝继续。

## 验证证据

- 真实隔离 WordPress 测试累计 **129 项断言通过**，其中此前 schema/查询恢复 64 项，新删号测试 65 项。
- 向 SELECT、audit/outbox/requests DELETE、COMMIT 分别注入合成 SQL 错误，逐次确认失败且三张表的全部行保持原样。
- MyISAM 状态在任何 DELETE 前拒绝；修复仅测试表引擎后，关闭功能且删除 schema option 的情况下清理成功。
- 两个合成用户验证隔离；重复删除幂等、非法用户 ID 拒绝、全部关联合成数据最终为空。
- PHP 插件契约、推送所有权与 worker 回归通过。轻量契约提供合成 schema 元数据只是为了测试删除门禁，不能代替上述真实引擎/回滚证据。
- 独立 486 项 schema 元数据/故障断言、源码门禁与供应链契约通过；macOS 不具备的 PHP/Composer 和 Linux flock 未冒充本地执行。PHP 另在 Linux 隔离夹具验证，宿主只读计数确认随机 WordPress 测试库残留为 0。
- 真实数据库夹具仍禁止宿主网络、生产 Webroot/配置读取和邮件/HTTP 发送；使用随机空测试库并在 finally 精确移除。
- 本增量未修改 App 页面、播放器或用户权限；独立分支不取消主线当前 UI 测试。
